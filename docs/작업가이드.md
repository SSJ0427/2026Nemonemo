# 작업 가이드

각자 무엇을 어디서 시작하면 되는지 정리한 문서. 설치는 [README](../README.md), 브랜치·커밋 규칙은 [CONTRIBUTING](../CONTRIBUTING.md) 참고.

## 앱 범위 (지키기)

- **로그인 · 회원가입 · 서버 없음.** 앱을 켜면 바로 카메라 스캔 화면이 뜬다.
- 결과는 휴대폰 안(앱 문서 폴더)에 저장하고, 공유 시트로 내보낸다. 네트워크를 쓰지 않는다.
- 권한은 **카메라 하나**만 쓴다. 새 권한이 필요하면 먼저 팀에 공유한다.
- 화면은 두 개: `ScanScreen`(실시간 스캔) → `ResultScreen`(모드 선택 · 저장 · 공유). 선택 기능도 이 흐름 안에 붙인다.

## 작업 흐름 (한 기능 기준)

```
1. 이슈 만들기      GitHub Issues → "작업" 또는 "실험" 템플릿
2. 브랜치           git switch -c feat/edge-auto-canny
3. Python 실험      python/scanner/*.py 수정, experiments/*.py 로 비교
4. 결과 기록        docs/실험기록/ 에 표·그림 요약 (보고서 재료가 된다)
5. Dart 이식        app/lib/pipeline/*.dart 를 같은 동작·같은 값으로 수정
6. 테스트           cd python && pytest   /   cd app && flutter analyze && flutter test
7. PR              템플릿의 체크리스트 채우고 1명 이상 리뷰 → merge
```

- 값만 바꾸는 경우에도 Python 상수(`SIGMA`)와 Dart 상수(`kSigma`)를 **같이** 바꾼다. 한쪽만 바꾸면 `tests/test_params_sync.py` 가 실패한다.
- 실험만 하고 merge 하지 않을 거라면 `exp/<이름>-<내용>` 브랜치를 쓴다.

## 통합할 때 지킬 약속

- 함수 이름·입출력은 계획서 6장 인터페이스를 그대로 쓴다. 바꿔야 하면 이슈로 먼저 공유한다.
- 꼭짓점 순서는 항상 **좌상 → 우상 → 우하 → 좌하**. 앱에서 화면 사이로 넘길 때는 0~1 로 정규화한다.
- Dart 에서 만든 `cv.Mat` 은 다 쓰면 `dispose()` 한다 (안 하면 라이브 루프에서 메모리가 샌다).
- `cv.Mat` 은 Isolate 사이로 보낼 수 없다. 바이트(`Uint8List`)나 `Quad` 로 주고받는다.
- 무거운 처리는 UI 스레드가 아니라 `Isolate.run` 안에서 한다.

## 자주 막히는 곳

| 증상 | 해결 |
|---|---|
| `flutter pub get` 에서 SDK 버전 오류 | Flutter stable 3.44 이상으로 `flutter upgrade` |
| 첫 빌드가 30분 넘게 걸림 / CMake 오류 | Android Studio SDK Tools 에서 NDK · CMake 설치 확인, 로그를 단톡에 바로 공유 |
| Windows 에서 `flutter test` 실패 | Visual Studio "C++ 데스크톱 개발" 설치 필요. 안 되면 GitHub Actions → "Dart test" 수동 실행 |
| 앱에서 사각형이 90도 돌아가 보임 | 기종 정보와 함께 버그 이슈 등록 (전성재) |
